# 提案書仕様書（SPEC）作成スキル

## 概要

提案書の「仕様書」をMarkdown形式で生成するスキル。この仕様書を NotebookLM、スライド作成AI、Claude などに渡すことで、一貫性のある高品質な提案書スライドを作成できる。

**出力物：** 提案書仕様書（Markdown）
- 各スライドの内容・構成
- 見せ方の設計意図
- Mermaidによる図解（フローチャート、ガントチャート等）
- 表形式のデータ

## ワークフロー

### Step 1: 要件ヒアリング（必須）

**仕様書作成前に、必要な情報が揃っているか必ず確認する。不足があればユーザーに質問してから作成を開始する。**

#### 必須情報（これがないと仕様書を作成できない）

| 項目 | 例 | 確認質問 |
|------|----|---------| 
| 提出先企業名 | スミセイ情報システム様 | 「提出先の企業名を教えてください」 |
| プロジェクト概要 | AIチャットボット導入PoC | 「どんなプロジェクトの提案ですか？」 |
| 解決したい課題 | サポートセンターの工数削減 | 「クライアントが抱えている課題は何ですか？」 |
| 提案内容の概要 | Dify+MCPでAIエージェント構築 | 「どんなソリューションを提案しますか？」 |

#### 推奨情報（あるとより良い仕様書になる）

| 項目 | 例 | 確認質問 |
|------|----|---------| 
| 予算感 | 300万円程度 | 「予算感や見積もり金額はありますか？」 |
| 期間 | 3ヶ月 | 「プロジェクト期間の想定はありますか？」 |
| 提案者の強み | 業界経験16年、AI研究機関出身 | 「御社の強みや実績で強調したい点はありますか？」 |
| 体制 | PM1名、エンジニア2名 | 「想定している体制はありますか？」 |
| 過去の類似実績 | 〇〇社でのAI導入支援 | 「類似の導入実績はありますか？」 |

#### ヒアリングのルール

1. **必須情報が1つでも欠けている場合**：仕様書作成を開始せず、まず質問する
2. **質問は1〜3個ずつ**：一度に大量の質問をしない
3. **推奨情報は任意**：なければデフォルト値や「要確認」で進める
4. **既存情報の活用**：ユーザーが添付した資料やこれまでの会話から情報を抽出してから質問する

#### ヒアリング例

```
提案書仕様書を作成するために、いくつか確認させてください。

1. 提出先の企業名を教えてください（「〇〇様」形式で記載します）
2. どんな課題を解決する提案ですか？
3. 提案するソリューションの概要を教えてください

※予算や期間、体制などは後からでも追加できます。
```

### Step 2: 構造パターン選択

**パターンA：技術実装型**（PoC、システム開発向け）
**パターンB：組織変革型**（DX推進、コンサル向け）

詳細は `references/proposal-structure.md` 参照。

### Step 3: 仕様書生成

各スライドの仕様を以下のフォーマットで記述：

```markdown
## スライドN: [タイトル]

### 目的
このスライドで伝えたいこと

### 見せ方
- レイアウト構成
- 視線の誘導
- 強調ポイント

### コンテンツ
実際の内容（テキスト、表、図）

### 設計意図
なぜこの見せ方をするのか
```

各スライドタイプの詳細は `references/slide-specs.md` 参照。

### Step 4: Markdown要素の活用

**使用可能な要素：**
- 見出し（#, ##, ###）
- 表（| col1 | col2 |）
- Mermaidフローチャート（```mermaid flowchart）
- Mermaidガントチャート（```mermaid gantt）
- 箇条書き・番号リスト
- 強調（**太字**、*斜体*）
- 引用（> ）

### Step 5: 出力

`.md`ファイルとして出力。ファイル名例：
`〇〇様_△△プロジェクト_提案書SPEC.md`

## 仕様書の基本構造

```markdown
# [プロジェクト名] 提案書仕様書

## メタ情報
- 提出先：〇〇様
- 提案者：株式会社△△
- 作成日：YYYY-MM-DD
- バージョン：1.0

## 全体設計
### コンセプト
### カラースキーム
### トーン＆マナー

## スライド仕様
### スライド1: タイトル
### スライド2: 目次
...
```
