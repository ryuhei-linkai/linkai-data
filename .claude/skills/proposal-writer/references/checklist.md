# 提案書仕様書 品質チェックリスト

## □ メタ情報

- [ ] 提出先企業名が正確に記載されている
- [ ] プロジェクト名が明確
- [ ] 作成日・バージョンが記載されている
- [ ] 提案者情報が含まれている

## □ 全体設計

- [ ] コンセプト（提案の核となるメッセージ）が明確
- [ ] カラースキームが指定されている（メイン、アクセント、背景）
- [ ] トーン＆マナー（堅め/柔らかめ、技術的/ビジネス的）が定義されている
- [ ] スライド数の目安が示されている

## □ 構造設計

- [ ] 「課題→解決策→実行計画→価値証明→価格」の流れがある
- [ ] 各スライドに「目的」が明記されている
- [ ] 各スライドに「見せ方」が記述されている
- [ ] 各スライドに「設計意図」が説明されている
- [ ] 抽象→具体の段階的開示になっている

## □ 与件整理スライド

- [ ] 大目標（クライアントのゴール）が明示されている
- [ ] 課題がゴールから逆算で導出されている
- [ ] 各課題に対応する解決の方向性がある
- [ ] 今回のスコープが明確に区別されている
- [ ] 逆ピラミッド構造の図解がある

## □ 提案概要スライド

- [ ] アーキテクチャ/システム構成が図解されている
- [ ] レイヤー構造が明確
- [ ] 今回構築する範囲が強調されている
- [ ] 将来の拡張ポイントが示唆されている

## □ フェーズ構成

- [ ] Phase分けで将来展開を示している
- [ ] 「検証で終わらせない」将来ビジョンがある
- [ ] 各Phaseの目的・ゴールが明確
- [ ] 時間軸が示されている

## □ スケジュール

- [ ] ガントチャート（Mermaid gantt）がある
- [ ] タスクの親子関係が明確
- [ ] 担当区分が示されている
- [ ] マイルストーンが定義されている
- [ ] 月単位の時間軸がある

## □ 体制

- [ ] 組織図がある
- [ ] 各役割の責任範囲が明確
- [ ] コミュニケーション計画（頻度、ツール）がある
- [ ] 「One Team」の協働姿勢が示されている

## □ 強み・差別化

- [ ] 3〜5個のキーワードで強みが整理されている
- [ ] 「技術」×「業界知見」の掛け算がある
- [ ] 具体的な数値実績がある
- [ ] 競合との差別化ポイントが明確

## □ 見積もり

- [ ] 合計金額が明示されている
- [ ] 内訳（役割別、工数別）がある
- [ ] 税別/税込が明記されている
- [ ] 補足事項（除外項目、前提条件）がある
- [ ] ROI分析がある（組織変革型の場合）

## □ 実績

- [ ] 「背景→ソリューション→成果」形式で記述されている
- [ ] 定量的成果（数値）がある
- [ ] 提案先と類似の業界・課題の事例を選んでいる

## □ 数値の具体化

| 項目 | NG | OK |
|------|----|----|
| 期間 | 約3ヶ月 | 2025年7月〜10月（4ヶ月間） |
| 金額 | 数百万円 | ¥3,100,000（税別） |
| 精度 | 高精度 | 正答率99.8% |
| 速度 | 高速 | 応答速度0.4秒 |
| 経験 | 豊富な経験 | 16年間の業界経験 |
| 効果 | 大幅削減 | 工数1/5に削減 |

## □ Mermaid図解

- [ ] 課題構造図（逆ピラミッド）がある
- [ ] アーキテクチャ図がある
- [ ] ガントチャートがある
- [ ] 体制図がある
- [ ] 色の使い方が統一されている
- [ ] 要素が詰め込みすぎになっていない

## □ 心理テクニック

- [ ] 冒頭でクライアントの課題を「代弁」している
- [ ] 将来ビジョン（半年後、1年後）を提示している
- [ ] 長期パートナーシップを示唆している
- [ ] 具体的な数字を多用している

## □ 最終確認

- [ ] 各スライドに「目的」「見せ方」「コンテンツ」「設計意図」が揃っている
- [ ] 仕様書を読めば、どんなスライドを作るべきかが明確にわかる
- [ ] NotebookLM / スライド作成AI / Claude に渡して使える状態になっている
- [ ] ファイル名が適切（例：〇〇様_△△プロジェクト_提案書SPEC.md）
