# 提案書構造パターン詳細

## パターンA：技術実装型提案

PoC、システム開発、技術導入プロジェクト向け。

### 構造

```
1. 目次
2. 前提・ご相談内容の整理（課題の言語化）
3. 提案の全体像
4. 提案詳細①：プロジェクト計画
5. 提案詳細②：体制・進め方
6. 強み
7. お見積もり
8. 今後の展開
9. 開発実績
10. 会社概要
```

### 各セクションのポイント

**2. 前提・課題整理**
- クライアントの「痛み」を代弁
- 三層フレーム図で可視化（大目標→課題→方向性）
- 「核心技術」と「容易に改善可能な部分」を分離

**3. 提案の全体像**
- アーキテクチャ図（UI層→エージェント層→データ層）
- Phase構成（Phase 0/1/2）で将来展開を示唆
- 今回のスコープを明確化（赤枠等で強調）

**7. 見積もり**
- 合計金額を大きく表示（例：¥3,100,000）
- 人員別単価と工数内訳表
- 補足事項（除外項目、前提条件）

## パターンB：組織変革型提案

DX推進、AI導入支援、コンサルティング向け。

### 構造

```
1. サマリー（1スライドで全体把握）
2. 会社概要・選ばれる理由
3. AIアセスメント（導入プロセス）
4. ご提案の詳細
   - プロジェクト方向性
   - 年間プランニング
   - マイルストーン
   - KPI
5. プログラムの特徴
6. ガバナンス体制
7. 導入事例
8. 実施体制
9. デモ紹介
10. お見積り
11. 会社概要（再掲）
```

### 各セクションのポイント

**1. サマリー**
- ビジョン起点：「半年で〜、1年で〜」
- 投資額とROIを明示
- 1スライドで意思決定者が全体把握可能

**4. 提案詳細**
- 12ヶ月ロードマップ（M0〜M12）
- 色分けによるカテゴリ区別（研修、ツール、実践、経営）
- KPIをカード形式で表示（80%、20%+、週300件等）

**6. ガバナンス体制**
- 4層構造：
  1. Steering Committee（役員層）：隔月
  2. PMO+ベンダー：週次
  3. DX-Core（社内運用）：日次
  4. 部門Champion：現場展開

**10. 見積もり**
- 項目別内訳（コンサル/PMO、研修、ツール利用料）
- ROI分析を必須で付加（投資額→効果見込み→倍率）
- リソース配分の可視化（パーセンテージバー）

## 構造設計の黄金法則

### 「課題→解決策→実行計画→価値証明」フレーム

| フェーズ | 目的 | 含める要素 |
|---------|------|----------|
| 課題の言語化 | クライアントの「痛み」を代弁 | 現状課題、与件整理 |
| 解決策提示 | 「私たちなら解決できる」を示す | アーキテクチャ、アプローチ |
| 実行計画 | 「どう実現するか」の具体化 | スケジュール、体制 |
| 価値証明 | 「信頼に値する」を証明 | 実績、強み、KPI |
| 投資対効果 | 意思決定を促進 | 見積もり、ROI |

### 「段階的開示」の原則

- **抽象→具体**の流れを徹底
- 最初に全体像、次に詳細へ
- 「提案の全体像」→「提案詳細①②」

### フェーズ/ステップ構成

**技術実装型（3フェーズ）**
```
Phase 0: 今回のPoC（業務への実用化判断の基盤を作る）
Phase 1: 次の段階（収益向上への貢献）
Phase 2: 将来的な展望（AIエージェントの拡大・SaaS化）
```

**組織変革型（2フェーズ/12ヶ月）**
```
Phase 1 (0-6M): Engage & Quick Wins
  - 起案→導入→実践開始
Phase 2 (6-12M): Scale & Institutionalize
  - 定着→深化→自走化
```
