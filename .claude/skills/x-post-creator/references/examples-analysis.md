# 参考ポスト分析

## 分析サマリー

参考ポストから抽出した成功パターン：

| 要素 | パターン |
|-----|---------|
| フック | 問いかけ、逆説、速報 |
| 構造 | 過去→現在、問題→解決、比較 |
| 本質提示 | 「つまり〜」「要するに〜」 |
| 締め | 問いかけ、行動提案 |
| トーン | 断定と柔らかさの混在 |

---

## 個別分析

### 1. SQLポスト（深津さん風・歴史文脈型）

**構造分析**
```
1. 問いかけフック「〜知ってます？」
2. 過去の技術紹介
3. 当時の期待「〜と宣言されました」
4. 実際の結末「その後どうなったか？」
5. 現在との類似「今、似たようなことが〜」
6. 本質の抽出
7. 問いかけで締め
```

**成功要因**
- 歴史から学ぶ構造で説得力
- 「普通の人」視点で共感を得る
- 技術の本質を人間心理に落とし込む
- 問いかけで読者を巻き込む

**抽出できるテクニック**
- 50年のスパンで比較（長い時間軸で信頼性UP）
- 豆知識を挟む（「Mac版だったんです。テストに出るよ」）
- 二項対立で締める（「どちら側の人ですか？」）

### 2. チャエンさんポスト（速報＋解説型）

**構造分析**
```
1. (1/n) 全体要約
2. (2/n) 【なぜ今〜】背景
3. (3/n) 【〜とは】具体内容
4. (4/n) 【〜の5原則】詳細
5. (5/n) 詳細続き
6. (6/n) まとめ・競合状況
```

**成功要因**
- スレッド形式で読みやすい
- 【見出し】で構造化
- 数字・具体例が豊富
- ソース明記で信頼性

**抽出できるテクニック**
- 絵文字で視認性UP（1️⃣2️⃣3️⃣）
- 金額・数字を具体的に
- 競合比較で文脈を示す
- プラン比較で整理

---

### 3. 社内AI驚き屋ポスト（概念提唱型）

**構造分析**
```
1. 概念名の提示「〜が重要なのではと思ってきた」
2. 背景（AIの特性：進化が速い、体系化しづらい）
3. 課題（活用ノウハウは現場から生まれやすい）
4. 解決策（驚き屋の役割説明）
5. メカニズム（情報×課題→アイディア）
6. なぜ内部に閉じるか
7. 結論「だから〜」
```

**成功要因**
- キャッチーな名前（驚き屋）
- 論理展開が明確
- 「→」で因果関係を示す
- 組織導入の実感に基づく

**抽出できるテクニック**
- 新しい役割・概念に名前をつける
- 「〜なので」「よって」「すると」で論理をつなぐ
- 箇条書きと文章を混ぜる

### 4. Cursor公式ブログ紹介ポスト（対比・構造型）

**構造分析**
```
1. ソース明示「〜の公式ブログによる」
2. テーマ提示「〜編」
3. A の特徴（箇条書き）
4. B の特徴（箇条書き）
5. 補足情報
6. 結論
7. ソースURL
```

**成功要因**
- 公式情報という信頼性
- 比較形式でわかりやすい
- 結論が明確
- 実用的な示唆

**抽出できるテクニック**
- ○で項目を示す
- ・で詳細を示す
- 「結論」と明示する
- 「万能〜ではなく」の否定＋肯定構文

### 5. McKinsey記事紹介ポスト（速報＋洞察型）

**構造分析**
```
1. フック「AI時代こそ読んで欲しい記事」
2. 要約導入「＞」
3. 状況説明
4. 数字で補強
5. 「ここからが面白い」で転換
6. 意外な発見
7. 本質「つまり〜」
8. ソースURL
```

**成功要因**
- 「面白い」で興味を引く転換
- 具体的な数字（6万人、4万人、2万のAI）
- 意外性のある結論（挫折経験→パートナー昇進）
- 大手企業の事例で説得力

**抽出できるテクニック**
- 「背景の数字がすごい」で数字への注目を促す
- 引用符「」で発言を引用
- 「ここからが面白い」で読み進めさせる

### 6. 思考系ポスト（実践知型）

**例：AIキャッチアップの順序**
```
うーん、やっぱり[結論]

[比較：AよりもBの方がいい]

[理由]
```

**成功要因**
- 「うーん」で思考過程を見せる
- 短く端的
- 矢印「→」で流れを示す
- 実感に基づく

---

### 7. System 1/2 解説ポスト（知識体系型）

**構造分析**
```
1. テーマ提示「知っておいたほうがいい」
2. 概念の簡潔な説明
3. LLMへの接続
4. 自分の体験談
5. 兄弟との会話（具体例）
6. 学び・示唆
7. 今後への期待
```

**成功要因**
- 既存の理論を紹介
- 自分の経験で親近感
- 会話形式で読みやすい
- LLMへの応用で実用性

**抽出できるテクニック**
- 「■」で見出し
- 会話形式「ワイ「〜」」
- 「つまりなにが言いたいかというと」で要約
- 「※」で補足

## 共通する成功パターン

### トーン
- 断定と柔らかさのバランス
- 「〜だと思う」「〜ではないか」
- 「ぶっちゃけ」「うーん」で人間味

### 構造
- 明確な論理展開
- 「つまり」「要するに」で本質提示
- 問いかけで読者を巻き込む

### 具体性
- 数字を入れる
- 固有名詞を入れる
- ソースを明示

### 独自性
- 自分の視点・解釈を加える
- 歴史や他分野と接続
- 新しい名前・フレームワークを提案
