## ① ミッション

### 見出し
**すべてのプロジェクトには、ミッションがある。**

### 本文
会社も、チームも、プロジェクトも。
すべては、一つのミッションを達成するために存在している。

宇宙に進出する。エネルギーを生み出す。教育を届ける。新しい技術を社会に実装する。
社会を前に進めるミッションは、いつも複雑で、簡単には達成できない。

だから人は、プロジェクトを組む。
多様なスキルを持った人々が集まり、複雑に連携しながら、一つの方向に進んでいく。

AIの進化で、一つひとつの作業は驚くほど速くなった。
スライドを作る、コードを書く、データを分析する——
私たちはもっと本質的なことに向き合えるようになった。

では、本質的なこととは何か。

ミッションから逆算して、何をすべきかを定めること。
何が足りないのかを見つけ、打ち手を決めること。
人がより大きな価値を生み出すことに集中できるようにすること。
AIが、プロジェクトの文脈を理解した上で、その力を最大限に発揮できるようにすること。

つまり——プロジェクトを、推進すること。

**SUISHINは、その「推進」を担うAI。**

### 設計意図
- 冒頭から「ミッション」という大きなスケールで語り始める
- 社会を前に進めるプロジェクトの具体例を挟むことで、スケール感と共感を同時に得る
- AIの進化を肯定し、その先の問い（「では本質的なこととは何か」）に自然に導く
- 「人がより大きな価値を生み出すことに集中」「AIがプロジェクトの文脈を理解して力を発揮」
  → 人もAIも、プロジェクトの文脈があって初めて最大の成果を出せるというニュアンス
- 否定語なし、他プロダクトへの言及なし。純粋にSUISHINの使命だけを語る
- ダークトーン背景に白文字、余白多め。哲学を感じさせるトーン

## ⑤ 機能ディープダイブ：プランを策定する

### 見出し
**Scope 02 — プランを策定する**

### サブ見出し
ゴールを入力するだけで、実行可能な計画が生まれる。

### 2つの機能ブロックに分割

---

**ブロックA：タスク自動分解（WBS）**

- 左右2カラム（左：テキスト / 右：UI画面 or タスクツリー図）
- ゴールを入力 → AIが自動でタスクツリーを生成

表示例（タスクツリー）：
```
新サービスローンチ
├── 企画フェーズ（2週間）
│   ├── 市場調査・競合分析
│   ├── ターゲット定義
│   └── ビジネスモデル策定
├── 開発フェーズ（6週間）
│   ├── 要件定義
│   ├── UI/UXデザイン
│   ├── 開発・実装
│   └── テスト
└── ローンチフェーズ（4週間）
    ├── マーケティング準備
    ├── β版リリース
    └── 本番リリース
```

---

**ブロックB：ボトルネック特定 ★最大差別化**

- フルワイドで大きく見せる。このセクション内の目玉。

見出し：
**プロジェクトが止まる原因を、AIが見つけ出す。**

リード：
> 管理ツールは「タスクが遅れている」ことは表示する。
> SUISHINは「なぜ遅れているのか」を特定し、「どう解決するか」を提案し、実行に移す。

5ステップのフロー図：

```
📂 コンテキスト収集  →  💬 AIヒアリング  →  🔍 ボトルネック特定  →  🧠 原因分析  →  🎯 打ち手提案＆タスク登録
```

各ステップの説明（フロー図の下にコンパクトに）：

| ステップ | 説明 |
|---------|------|
| コンテキスト収集 | タスク・ファイル・議事録・プロジェクト概要を統合的に読み込む |
| AIヒアリング | プロジェクトの状況を対話形式で深掘りする |
| ボトルネック特定 | 何がプロジェクトを止めているかを特定する |
| 原因分析 | なぜそれが起きているか、根本原因を解明する |
| 打ち手提案＆タスク登録 | 具体的な解決策を提案し、そのままタスクとして登録する |

具体例（1つだけコンパクトに）：
> **例：** デザイン方針の未決定が開発タスク12件をブロック
> → 決裁者のレビューが2週間滞留していることが原因
> → ①決裁者にリマインド送信 ②レビュー会議を設定 ③暫定方針で開発先行 → 3タスクとして即座に登録

### 設計意図
- タスク自動分解は「便利機能」、ボトルネック特定は「SUISHINの本質」
- ボトルネック特定を大きく見せることで「これは管理ツールには絶対できない」と印象付ける
- 具体例1つで「なるほど、こういうことか」と腹落ちさせる
